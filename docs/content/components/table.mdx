# Table

The Table component provides you with data tables with sorting, pagination, and selection.

## Import

```tsx
import { Table } from "@jarllyng/nostromo";
// or
import { Table } from "@jarllyng/nostromo/table";
```

## Usage

```tsx
import { Table, type TableColumn } from "@jarllyng/nostromo";

// A type alias rather than an interface. `data` is typed `Record<string,
// unknown>[]`, and an interface has no index signature, so TypeScript refuses
// it where an equivalent alias is accepted.
type User = {
  id: string;
  name: string;
  email: string;
};

export default function Example() {
  const data: User[] = [
    { id: "1", name: "John Doe", email: "john@example.com" },
    { id: "2", name: "Jane Smith", email: "jane@example.com" },
  ];

  const columns: TableColumn<(typeof data)[number]>[] = [
    { key: "name", title: "Name", dataIndex: "name" },
    { key: "email", title: "Email", dataIndex: "email" },
  ];

  return <Table data={data} columns={columns} />;
}
```

## Advanced Examples

### With Sorting

<LiveCode code={`import { Table, type TableColumn } from '@jarllyng/nostromo'

type User = {
id: string
name: string
email: string
}

export default function SortableTable() {
  const [sortColumn, setSortColumn] = React.useState<string>()
  const [sortDirection, setSortDirection] = React.useState<'asc' | 'desc'>()
  
  const data: User[] = [
    { id: '1', name: 'John Doe', email: 'john@example.com' },
    { id: '2', name: 'Jane Smith', email: 'jane@example.com' }
  ]
  
  const columns: TableColumn<(typeof data)[number]>[] = [
    { 
      key: 'name', 
      title: 'Name', 
      dataIndex: 'name',
      sortable: true 
    },
    { 
      key: 'email', 
      title: 'Email', 
      dataIndex: 'email',
      sortable: true 
    }
  ]
  
  const handleSort = (column: any, direction: 'asc' | 'desc') => {
    setSortColumn(column.key)
    setSortDirection(direction)
    // Implement your sorting logic
  }
  
  return (
    <Table
      data={data}
      columns={columns}
      sortColumn={sortColumn}
      sortDirection={sortDirection}
      onSort={handleSort}
    />
  )
}`} />

### With Pagination

<LiveCode code={`import { Table, type TableColumn } from '@jarllyng/nostromo'

export default function PaginatedTable() {
  const [currentPage, setCurrentPage] = React.useState(1)
  const [pageSize, setPageSize] = React.useState(10)
  
  const data = Array.from({ length: 100 }, (_, i) => ({
    id: i + 1,
    name: \`User \${i + 1}\`,
    email: \`user\${i + 1}@example.com\`
  }))
  
  const columns: TableColumn<(typeof data)[number]>[] = [
    { key: 'name', title: 'Name', dataIndex: 'name' },
    { key: 'email', title: 'Email', dataIndex: 'email' }
  ]
  
  return (
    <Table
      data={data}
      columns={columns}
      pagination={{
        current: currentPage,
        pageSize: pageSize,
        total: data.length,
        onChange: (page, size) => {
          setCurrentPage(page)
          setPageSize(size)
        },
        showSizeChanger: true
      }}
    />
  )
}`} />

| Prop               | Type                                                                 | Default     | Required | Description                                 |
| ------------------ | -------------------------------------------------------------------- | ----------- | -------- | ------------------------------------------- |

## Selection spans pages, the checkbox does not

`selectedRowKeys` is the whole selection. It can name records that are not on the
page being rendered, and the Table never discards them.

That shapes two things worth knowing.

**Select-all acts on this page.** It adds every selectable row you can currently
see to the selection, or removes them, and leaves every other key untouched. Its
checked state is read the same way: all of the selectable rows on this page, some
of them, or none. Keys belonging to other pages neither check it nor leave it
indeterminate.

**A disabled row is skipped, not selected for you.** `getCheckboxProps` returning
`{ disabled: true }` takes the row out of select-all as well as out of its own
checkbox. Once every row that can be selected is selected, select-all reads as
checked rather than staying permanently indeterminate because of the rows that
cannot be.

## The keys are authoritative, the records are what is on screen

`onChange` gives you both:

```tsx fragment
onChange={(keys, rows) => { ... }}
```

`keys` is the complete selection. `rows` is only the subset present in `data`,
because the component has never been given the rest. If you paginate server-side,
keep your own key-to-record map and treat the keys as the source of truth.

## Zero is a key

`rowKey` falls back to the row's index only when the value is `null` or
`undefined`. A record with `id: 0`, or an empty-string key, keeps its own key.
